# Прозрачная вакансия

MVP сервиса анализа качества описаний вакансий Калининградской области (код региона `39`) из открытого API портала «Работа России».

## Что делает сервис

- Загружает вакансии из API `.../vacancies/region/39`.
- Запрашивает страницы через `offset` и `limit` (до 100 записей на страницу); по умолчанию обрабатывает две страницы.
- Удаляет дубликаты в пределах запуска по ID вакансии.
- Анализирует должность, обязанности, требования, оплату, график, место работы и тип занятости.
- Использует локальную LLM через Ollama. Модель возвращает структурированные замечания: пропуск, неоднозначность или противоречие.
- Проверяет, что цитаты модели действительно содержатся в исходном поле. Не подтверждённая цитата отбрасывается.
- Формирует JSON-отчёт; если замечаний нет, `remarks` равен пустому массиву.
- Сохраняет последний успешный отчёт. При ошибке API или модели новый отчёт не записывается.
- Поддерживает автономную проверку локального JSON без обращения к порталу.

## Требования

- Python 3.10+
- Ollama и локальная модель `qwen2.5:3b` (или другая совместимая chat-модель).

Установка модели (один раз):

```bash
ollama pull qwen2.5:3b
```

Запустите Ollama в фоне/отдельном терминале. Ключи внешних API не требуются.

## Установка и запуск

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd transparent-vacancy
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
python main.py run
```

Linux/macOS:

```bash
source .venv/bin/activate
cp .env.example .env
python main.py run
```

По умолчанию загружаются две страницы по 100 записей:

```bash
python main.py run --pages 2 --limit 100
```

Настройки можно менять переменными окружения из `.env.example`. Для простого MVP `.env` не требует секретов.

## Проверочный режим

Проверочный режим получает локальный JSON, анализирует его тем же модулем ИИ и не обращается к API:

```bash
python main.py verify data/sample_api_response.json --output reports/verification.json
```

Файл должен содержать официальный формат `{"results":{"vacancies":[{"vacancy":{...}}]}}`, массив вакансий либо массив объектов `vacancy`.

## Формат отчёта

```json
{
  "schema_version": "1.0",
  "generated_at": "2026-11-25T08:00:00+00:00",
  "mode": "live",
  "source": "https://opendata.trudvsem.ru/api/v1/vacancies/region/39",
  "region_code": "39",
  "vacancies_count": 1,
  "vacancies": [
    {
      "id": "12345",
      "url": "https://trudvsem.ru/...",
      "remarks": [
        {
          "topic": "График работы",
          "source_field": "schedule",
          "quote": "Гибкий график",
          "issue": "Не указаны дни и временные интервалы работы.",
          "recommendation": "Уточнить дни недели, продолжительность смены и время начала и окончания работы.",
          "kind": "ambiguity"
        }
      ]
    }
  ]
}
```

Текст внутри примера — иллюстрация структуры, а не результат анализа реальной вакансии. Цитата должна подтверждаться исходным значением. Для пропуска `quote` остаётся пустой строкой.

## Архитектура

```text
main.py
└── app/
    ├── cli.py          # команды run / verify
    ├── config.py       # настройки из окружения
    ├── source.py       # HTTP, пагинация, разбор ответа API
    ├── normalizer.py   # унификация полей API
    ├── ai_analyzer.py  # запрос к локальной LLM и валидация её ответа
    ├── report.py       # JSON-схема и атомарное сохранение
    └── pipeline.py     # последовательность обработки
```

## Обработка ошибок и повторных запусков

1. Данные загружаются постранично. Дубли внутри одного запуска объединяются по ID.
2. Если запрос к API завершается ошибкой, обработка прекращается.
3. Если локальная модель недоступна или возвращает невалидный ответ, обработка прекращается.
4. Новый отчёт записывается только после успешного анализа всего набора. Запись выполняется через временный файл и атомарную замену.
5. `reports/last_successful_report.json` содержит последний успешно сформированный отчёт. Неудачный запуск его не перезаписывает.

Идентичные вакансии при повторном запуске не создают дубликатов внутри одного отчёта: каждый ID представлен одним объектом. Изменившаяся вакансия анализируется заново.

## Использование ИИ и ограничения

ИИ применяется для семантического этапа: различает неопределённые формулировки, отсутствующие условия и внутренние противоречия. Это не юридическая экспертиза. Сервис не определяет форму собственности работодателя и не делает выводов о нарушении закона. Рекомендации формулируются как вопросы на уточнение.

Качество анализа зависит от модели. Для воспроизводимости в демонстрации следует зафиксировать имя и версию модели, настройки и входной JSON.

## Источник данных

Открытый API «Работа России»: <https://opendata.trudvsem.ru/api/v1/vacancies/region/39>

Документация API: <https://trudvsem.ru/opendata/api>

Документация указывает GET-запросы, JSON-ответы, пагинацию через `offset` и `limit`, максимум 100 записей на страницу и параметр `total` в метаданных ответа.
